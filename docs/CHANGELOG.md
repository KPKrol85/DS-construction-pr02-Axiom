# Changelog

All significant changes to this project are documented in this file.

Recorded history begins with the initial standalone repository import; the entries below describe the implementation verified in the current project state.

## [Unreleased]

### Added

- Added the initial Axiom construction website implementation: home page, six service subpages, five legal subpages, a form success page, an offline page, and a custom 404 page.
- Added interactive front-end components: mobile navigation with synchronized `aria-expanded` state, theme toggle, compact header on scroll, back-to-top button, gallery lightbox with focus trap, and a cookie consent modal.
- Added a contact form with client-side validation, an accessible error summary, a message character counter, a honeypot field, and Netlify Forms with reCAPTCHA submission routed to `success.html`.
- Added flash-free theme initialization in `js/theme-init.js`, applying the stored theme or the `prefers-color-scheme` preference before first paint.
- Added a service worker with a versioned precache, network-first document handling, stale-while-revalidate for styles and scripts, cache-first images, and an `offline.html` fallback.
- Added PWA installability metadata in `manifest.webmanifest`, including maskable icons, application shortcuts, and store screenshots.
- Added SEO metadata across all pages: canonical URLs, Open Graph and Twitter tags, JSON-LD structured data, `robots.txt`, and a `sitemap.xml` covering twelve public URLs.
- Added a layered CSS architecture aggregated by `css/main.css` (`tokens`, `base`, `layout`, `components`, `sections`) with `prefers-reduced-motion` handling in animated sections.
- Added guarded `localStorage` access in `js/utils/storage.js` so theme and cookie-consent state degrade silently when browser storage is unavailable.

### Fixed

- Converted the careers form into an explicitly non-operational demonstration interface by disabling all recruitment-data and CV controls, removing its submission path, and stating that real applications are not accepted or processed (P1-02).
- Restored offline retry and automatic recovery by loading `js/offline.js` from `offline.html`, updating the connection-status live region, and adding the script to both local and production Service Worker precache profiles and revision inputs (P1-03).
- Corrected the reveal hidden state by scoping it to the existing `html.js` enhancement marker, keeping reveal content visible without JavaScript while preserving the scroll animation when JavaScript is active (P1-04).

### Build and Tooling

- Added a Node-based release pipeline (`build:clean` → `build:css` → `build:js` → `build:sw` → `build:dist`) producing `dist/style.min.css`, `dist/script.min.js`, a generated `dist/sw.js`, and the copied static deployment tree.
- Added service worker generation from `sw.template.js` with a precache revision hashed from the built stylesheet, the built script, and `manifest.webmanifest`.
- Added a `sharp`-based responsive image pipeline generating WebP and AVIF variants at fixed widths (`npm run img:build`, `npm run img:clean`).
- Added `tools/html/build-head.mjs` with `tools/templates/head.partial.html` and `tools/templates/pages.meta.json` as the single source for per-page `<head>` metadata.
- Added local preview servers for the working tree and for production output (`npm run serve`, `npm run serve:dist`).
- Added ESLint flat configuration (`eslint.config.mjs`) covering the browser ES Modules in `js/`, the Node `.mjs` tooling in `tools/`, and the `sw.template.js` service worker source, each linted in its own execution environment.
- Added `npm run lint` for the canonical JavaScript sources, with generated and minified output (`dist/`, the generated `sw.js`, `*.min.js`) excluded from linting.
- Removed redundant escape characters from template literals in `tools/js/build-js.mjs`, the only source correction required by the lint baseline.
- Added `/reports/` to the root `.gitignore`, completing the ignore contract that keeps the dependency directory, the generated `dist/` output, and the QA report output outside the committable working tree.
- Aligned the `_headers` cache policy with the paths the build actually produces: the production bundles `style.min.css` and `script.min.js` now carry explicit finite, revalidated cache rules instead of inheriting the global fallback; the unversioned CSS and JavaScript sources copied into `dist/` no longer receive one-year `immutable` caching, including `js/theme-init.js`, which production pages load directly; fixed-name images and `manifest.webmanifest` keep finite browser caching without `immutable`; the version-segmented self-hosted font paths retain long-lived `immutable` caching; and the stale `/assets/icons/*` rule, which matches no directory in the built output, was removed.
- Reduced the shipped image set to the files production actually requests: `tools/images/build-images.mjs` now derives its output from the widths and formats the page `srcset` declarations consume, instead of applying a fixed width ladder and both formats to every source, and it fails the run when a declared source stops producing output; the unreferenced source images, including the `-dup` duplicates and the unused `instalacja-elektryczna-01-*` set, and the stale `assets/img/_optimized/` variants that no page requests were removed, taking `assets/img/` from 1547 to 543 files (157.0 MiB to 110.6 MiB) and `assets/img/_optimized/` from 1072 to 164 files; `dist/assets/img/` now contains no file that a page, `manifest.webmanifest`, or the production precache contract does not request, and `npm run qa:references` and the production build both pass after the cleanup.
- Gave the root service worker a declared owner: `sw.template.js` is now the single canonical, hand-edited service-worker source, and `tools/sw/build-sw.mjs` renders it through one substitution step to generate both the root `sw.js` and the production `dist/sw.js`, so no service worker in the repository can drift from the template without the build producing it; the generator declares two explicit precache profiles — a local profile covering the assets the repository root actually serves (`/css/main.css`, `/js/main.js`, `/js/theme-init.js`) and the production profile keeping the built bundles (`/style.min.css`, `/script.min.js`), both sharing `/`, `/offline.html`, `/manifest.webmanifest`, and the manifest-derived icons, each with its cache revision hashed from the assets that profile precaches, and each generated file carrying a header naming its source, generator, and profile; the local service worker now installs and activates under the root development server (`npm run serve`) instead of failing its precache install, production continues to precache the production bundles from `dist/`, and `npm run build` and `npm run qa:references` both pass after the change.
- Corrected the indexing policy on the utility pages: `404.html` and `offline.html` now declare `noindex, follow`, matching the treatment `success.html` already carried, so no utility page presents itself as indexable; the policy is declared in `tools/templates/pages.meta.json`, which remains the canonical per-page metadata source that `npm run build:head` renders into each `<head>`, and `sitemap.xml` is unchanged, still limited to the existing twelve public URLs, none of which are utility pages; `npm run lint` and `npm run qa:references` both pass after the change.
- Established a single source for structured data: the inline `application/ld+json` blocks in the maintained HTML pages are now the canonical structured-data source, and the unused parallel `js/structured-data/` directory and its 15 JSON files, which no page, runtime module, build step, or QA script read, were removed; the structured data delivered to users and search engines is unchanged, with all 15 HTML pages byte-identical after the removal and every inline block still parsing as valid JSON, so the business, service, breadcrumb, and FAQ markup the pages already served is preserved exactly; `npm run lint` and `npm run qa:references` both pass after the change.
- Aligned the cookie policy with the consent mechanism the project actually provides: `legal/polityka-cookies.html` no longer implies that the site offers an in-site withdrawal or preference-management control, and now records that the accepted state is stored in the `cookie_consent` cookie and the `cookie-consent-v1` localStorage entry and can be cleared through the browser's site-data controls, which cover both cookies and browser storage; the consent dialog is unchanged, keeping its single acceptance control, focus trap, focus return, `Escape` suppression, and scroll lock.
- Removed inert configuration and dead code that advertised behavior the project does not implement: the comments-only `_redirects` file, which declared no active redirect rules, was removed, and `_redirects` was dropped from the `rootFilesToCopy` contract in `tools/release/build-dist.mjs`, so `build:dist` no longer expects or copies it; `postcss.config.json` was removed because the CSS pipeline never loaded it, as `tools/css/build-css.mjs` inlines `@import` with its own resolver before minifying through `cssnano-cli`, and the `postcss-import`, `postcss-nested`, and `postcss-preset-env` plugins it declared were never installed; and the unused `js/sections/faq.js` stub was removed, since nothing imported it and the FAQ is native `<details>` / `<summary>` markup; runtime and build behavior are otherwise unchanged, and `npm run lint`, `npm run qa:references`, and `npm run build` all pass after the change.
- Gave the production bundles content-addressed filenames, making long-lived immutable caching safe for the assets that dominate a repeat visit: a new `build:hash` step, placed between `build:js` and `build:sw` in `npm run build` (`build:clean` → `build:css` → `build:js` → `build:hash` → `build:sw` → `build:dist`), hashes the final minified bytes of the fixed intermediates `dist/style.min.css` and `dist/script.min.js` with SHA-256 truncated to 16 lowercase hexadecimal characters and renames them to `style.<hash>.min.css` and `script.<hash>.min.js` at the deployment root, recording the result in `dist/build-manifest.json`; that manifest is the shared source of truth, and the production HTML rewrite and the production service-worker precache both take the exact filenames from it instead of constructing their own; `build:dist` replaces a marker block in the copied `dist/_headers` with exact `Cache-Control: public, max-age=31536000, immutable` rules for those two URLs, while the unversioned `/css/*` and `/js/*` paths — `js/theme-init.js` included — keep their finite revalidated caching, the versioned font paths keep their existing policy, and the canonical root `_headers` remains hand-maintained; `tools/js/build-js.mjs` now emits modules in a deterministic order, so identical sources produce identical bundle bytes and therefore identical filenames across clean builds; and `npm run qa:references` was extended to validate the bundle naming contract statically without a build and, when `dist/build-manifest.json` exists, to verify the generated release as well — the bundles, the rewritten HTML, `dist/sw.js`, and `dist/_headers`; local development assets and the local service-worker profile are unchanged, and `npm run lint`, `npm test`, repeated clean `npm run build`, and `npm run qa:references` in both modes all pass after the change.
- Corrected the canonical public origin to `https://construction-pr02-axiom.netlify.app` across generated metadata, JSON-LD, `sitemap.xml`, and `robots.txt` (P1-01).
- Made `npm run build:head` idempotent: the head generator now normalizes the indentation of retained `<head>` script blocks instead of stacking another prefix on every run, and writes each page's own line-ending convention, so repeated executions leave all 15 pages byte-identical after the initial normalization, with the retained JSON-LD content unchanged (P2-01).
- Removed the blanket `X-Robots-Tag: all` directive from the global `/*` rule in `_headers`, so no response carries an HTTP indexing directive contradicting the page it serves: `404.html`, `offline.html`, and `success.html` keep `noindex, follow` as their single declared policy, and the per-page `<meta name="robots">` generated from `tools/templates/pages.meta.json` remains the one indexing-policy source for HTML pages; every other security and cache header in `_headers` is unchanged, `build:dist` still copies the canonical file and rewrites only the marked bundle-cache block, and `npm run qa:references` passes after the change (P2-02).
- Corrected the malformed dark-theme `--feature-hover-bg` token, which supplied `color-mix()` with a single colour and therefore produced no valid hover background: the dark declaration now mixes `--surface-2` with the theme's own `--feature-accent` (`color-mix(in srgb, var(--surface-2) 94%, var(--feature-accent) 6%)`), preserving the existing surface weighting and matching the two-colour shape the light theme already used, so feature cards, About highlight items, and FAQ hover, focus and open states gain a real dark-theme background shift; the fix is confined to the canonical token layer in `css/tokens/tokens.css`, leaving the light-theme token and every border, shadow, transform, focus, active and reduced-motion contract unchanged, and `npm run qa:references` passes after the change (P2-03).
- Corrected the single stylesheet rule that keyed off the operating-system colour preference in a theme system driven by `data-theme`: the active primary-navigation link's dark colour is now expressed through the project's existing `:root[data-theme="dark"]` selector instead of an `@media (prefers-color-scheme: dark)` block, so an explicit site-theme choice is respected in both directions — a visitor whose system prefers dark but who selects the light site theme now gets the light-theme colour (`--primary`), and the dark-theme colour (`--accent-400`) applies whenever the site is in dark theme; both colours are unchanged and the edit is confined to `css/components/utilities.css`, leaving the theme tokens, the `prefers-color-scheme` fallback that `js/theme-init.js` still uses to select the initial theme when no choice is stored, and the link's `aria-current` semantics, pointer-event and hover behavior, pseudo-element handling, font weight and layout untouched, and `npm run qa:references` passes after the change (P2-04).
- Removed the self-hosted Poppins font family, which no `@font-face` declared and no `font-family` declaration requested: the canonical `assets/fonts/poppins-v24-latin/` directory and both of its files — the unused `poppins-v24-latin-regular.woff2` binary and the bundled `OFL.txt` redistributed with it — were deleted, so the family can no longer reach the deployment through the recursive `assets/` copy in `build:dist` or receive one-year `immutable` caching from the `/assets/fonts/*` rule, and the attribution records were aligned with the material the repository actually redistributes: the Poppins subsection was removed from `THIRD-PARTY-NOTICES.md`, whose `## Fonts` preamble now describes two families instead of three, and the PL and EN attributions sections of `README.md` now name only Lato and Montserrat; the Lato and Montserrat binaries, license texts, `@font-face` declarations, preloads, and typography roles are unchanged, every family still stored under `assets/fonts/` is both declared and requested by the stylesheets, and `npm run qa:references` passes after the change (P2-05).

### Testing

- Added Lighthouse and pa11y QA runners (`npm run qa`) covering the home page, one service subpage, and one legal subpage, writing reports to `reports/`.
- Added `npm run qa:references`, a static reference-integrity check (`tools/qa/check-references.mjs`) that resolves the local references declared by the HTML pages, `css/**/*.css`, `manifest.webmanifest`, and the canonical production precache inputs owned by `tools/sw/build-sw.mjs`, reading only the tracked sources so it needs no local server and no browser; external, `mailto:`, `tel:`, `data:`, and same-document fragment references are ignored, unresolved references are reported with the source file that declares them and exit the run non-zero, and the precached generated bundle URLs (`/style.min.css`, `/script.min.js`) are validated against the build scripts that declare those outputs rather than against build output that exists only after `npm run build`.
- Made the QA audits self-contained: `tools/qa/run-lighthouse.mjs` and `tools/qa/run-pa11y.mjs` now start and stop their own local `http-server` through the shared `tools/qa/local-server.mjs` lifecycle helper, which waits for an actual HTTP response before the audit begins, stops the server it owns in `finally` including when an audit fails, and refuses to start with a clear message when port 8080 is already occupied rather than reusing or terminating a process it does not own; `npm run qa`, `npm run qa:lighthouse`, and `npm run qa:a11y` now run from a clean shell, so a separately started `npm run serve` is no longer required, and the audited URLs and report paths are unchanged.
- Added a focused automated test layer for the two most complex interactive modules: `vitest` with a `jsdom` environment runs `tests/contact-form.test.js` and `tests/lightbox.test.js` from the single `npm test` script, needing no local server and making no network request, with `vitest.config.mjs` pinning the jsdom URL to `http://localhost/` so the contact form's local submission path stays deterministic; 20 tests cover the contact form (required-field validation, focus on the first invalid field, the accessible error summary, the 500-character message limit and its counter, and the `contactFormMessage` draft being saved, restored, and removed after a successful submission) and the lightbox (opening and initial focus, the focus trap, focus return to the triggering gallery link, and `ArrowRight` / `ArrowLeft` navigation); the focus-trap test exposed one defect in `js/components/lightbox.js`, where the focusable-element snapshot was taken before the dynamically created previous, next, and fullscreen controls existed, so those controls did not participate in the trap on the first open — the controls are now created before the snapshot is taken, which is the only production change; ESLint coverage was extended to `tests/` and `vitest.config.mjs`, each with the globals it genuinely uses, so `npm run lint` now lints the test code as well.
