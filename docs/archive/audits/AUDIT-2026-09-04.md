# Axiom — Final Technical Front-End Audit

**Original audit date:** 2026-09-02
**Current-state review:** 2026-09-04
**Archived:** 2026-09-04
**Status:** ARCHIVED — 14 findings and improvements resolved or completed; P2-08 remained open.
**Scope:** Project-wide technical front-end, build, accessibility and release-integrity review.

## Overview

The review confirmed the resolution of four original P1 findings, seven original P2 findings and completion of three additional quality improvements.

The project demonstrated consistent HTML structure, defensive JavaScript initialization, centralized build ownership and automated reference validation.

One new release-integrity finding, P2-08, remained open: the tracked local Service Worker revision differed from its canonical inputs.

The assessment reflects repository state on 2026-09-04, not the project's current implementation.

## Verification summary

The following checks were performed during the review:

- **Vitest:** 33/33 tests passed across four files.
- **ESLint:** Passed without errors.
- **Reference integrity:** 1,347 local references resolved across 15 HTML pages, 20 CSS files, the PWA manifest and 11 statically checked precache entries.
- **HTML structure:** All 15 pages passed static checks for document landmarks, unique IDs, ARIA references, image alternatives and external-link attributes.
- **Structured data:** All 15 JSON-LD blocks parsed successfully.
- **Head generation:** Read-only execution confirmed byte-identical output across all 15 pages.
- **Service Worker:** Local revision synchronization failed; recorded as P2-08.

No production build, Lighthouse, pa11y, browser-level regression test or live-deployment verification was performed during this review.

## P0 — Critical risks

No critical findings were identified.

## P1 — Important findings

### [P1-01] Every canonical, social and sitemap URL names an origin that does not resolve

- **Status:** RESOLVED — verified.
- **Resolution:** Corrected the canonical origin to `https://construction-pr02-axiom.netlify.app` and synchronized metadata, JSON-LD, sitemap URLs and robots configuration.
- **Verification:** Source checks confirmed consistent origin references, and head generation remained byte-identical across 15 pages. Live URL and social-image availability were not rechecked.

### [P1-02] The careers form collects personal data and a CV with no submission path

- **Status:** RESOLVED — verified.
- **Resolution:** Converted the careers form into an explicitly disabled demonstration interface. Removed submission behavior and disabled personal-data, CV and consent controls while clearly communicating that applications were not accepted.
- **Verification:** Source inspection confirmed disabled controls, absent submission attributes and the demonstration notice in `legal/kariera.html`.

### [P1-03] The offline page's recovery controls are inert because their only script is never loaded

- **Status:** RESOLVED — verified.
- **Resolution:** Connected `js/offline.js` to the offline page and included it in both Service Worker precache profiles and revision inputs. Restored retry handling, connection announcements and automatic recovery wiring.
- **Verification:** Script loading, event handlers and precache declarations were verified in source. Browser-level offline recovery was not tested; the separate revision mismatch was recorded as P2-08.

### [P1-04] Most homepage content stays invisible when JavaScript does not run

- **Status:** RESOLVED — verified.
- **Resolution:** Restricted reveal-hidden styles to documents carrying the `html.js` enhancement marker. Preserved JavaScript-driven reveal animations while allowing content to remain visible without JavaScript.
- **Verification:** Source inspection confirmed that hidden reveal styles require the enhancement marker and that the existing reveal logic remains connected. Browser-level no-JavaScript behavior was not tested.

## P2 — Minor findings

### [P2-01] `npm run build:head` is not idempotent and reformats every page on each run

- **Status:** RESOLVED — verified.
- **Resolution:** Corrected script-indentation handling and preserved existing line endings during head generation.
- **Verification:** Read-only generator execution produced byte-identical output for all 15 maintained pages without modifying repository files.

### [P2-02] `X-Robots-Tag: all` contradicts the `noindex` policy the utility pages declare

- **Status:** RESOLVED — verified.
- **Resolution:** Removed the conflicting global `X-Robots-Tag` directive and retained page-specific robots metadata as the HTML indexing-policy source.
- **Verification:** Source inspection confirmed removal of the HTTP directive and preservation of `noindex, follow` for utility pages. Deployed response headers were not inspected.

### [P2-03] The dark-theme hover token uses `color-mix()` with a single colour

- **Status:** RESOLVED — verified.
- **Resolution:** Replaced the incomplete expression with a valid two-colour mix using `--surface-2` and `--feature-accent`.
- **Verification:** The corrected declaration and its consumers were verified in source, and reference checks passed. Rendered hover states were not retested.

### [P2-04] One rule keys off the system colour scheme in a theme system driven by `data-theme`

- **Status:** RESOLVED — verified.
- **Resolution:** Aligned active-navigation styling with the site's `data-theme` attribute instead of the operating-system colour preference.
- **Verification:** Source inspection confirmed removal of the conflicting CSS media-query override. Explicit theme combinations were not retested in a browser.

### [P2-05] A self-hosted font family is shipped but never used

- **Status:** RESOLVED — verified.
- **Resolution:** Removed unused Poppins assets and aligned font attribution with the retained Lato and Montserrat families.
- **Verification:** Font inventory and source references confirmed that both retained families have declarations and consumers, with corresponding OFL attribution.

### [P2-06] `README.md` points at archive files that do not exist

- **Status:** RESOLVED — verified.
- **Resolution:** Corrected PL and EN documentation references to the existing date-suffixed audit and plan archives.
- **Verification:** Referenced archive files existed, and obsolete unsuffixed paths were absent from the inspected README sections.

### [P2-07] Runtime code paths remain for controls and services the project does not have

- **Status:** RESOLVED — verified.
- **Resolution:** Removed the unused mobile theme-toggle branch, unsupported analytics calls and associated ESLint globals. Preserved the functional theme toggle and contact-form behavior.
- **Verification:** Source searches found no remaining `themeToggleMobile`, `gtag` or `fbq` references. The 33-test suite and ESLint passed.

### [P2-08] The tracked local Service Worker revision has drifted from its canonical inputs

- **Status:** OPEN — unresolved at the 2026-09-04 review.
- **Finding:** The generated local Service Worker revision was `5aeb3c3b22b4b154`, while tracked `sw.js` contained `c7eff6c576b9f79e`.
- **Evidence:** Read-only regeneration produced otherwise byte-identical output with the expected 13 precache entries. The revision token was the only difference.
- **Impact:** Previously installed local workers could retain an outdated static cache despite changes to canonical revision inputs.
- **Required verification:** Regenerate the worker through the canonical build process, verify byte-identical output and complete production-build and release-reference checks.

No remediation was performed for P2-08 during this review.

## Extra quality improvements

### Narrow what the production build copies into `dist/`

- **Status:** COMPLETED — source-verified.
- **Resolution:** Restricted the production payload to compiled bundles, required assets and the standalone `js/theme-init.js` and `js/offline.js` scripts.
- **Verification:** Build copy rules and production reference-validation contracts were inspected. Post-build enforcement was not executed during this review.

### Precache `js/theme-init.js` in the production service-worker profile

- **Status:** COMPLETED — source-verified.
- **Resolution:** Added the pre-paint theme initializer to production precaching and cache-revision inputs while retaining the existing local profile.
- **Verification:** Precache declarations and revision inputs were confirmed in source, and reference checks passed. Production Service Worker output was not generated during this review.

### Extend the focused test suite to the remaining focus-managing components

- **Status:** COMPLETED — verified.
- **Resolution:** Added navigation and project-information modal tests covering focus handling, keyboard interactions, ARIA state, scroll locking and consent persistence.
- **Verification:** All four Vitest suites passed (33/33), including the newly covered navigation and modal behavior.

## Verification limitations

The review primarily evaluated repository sources, generated-file contracts and automated unit tests.

The following areas were not independently verified:

- Production build output and post-build reference integrity.
- Lighthouse performance and accessibility measurements.
- Browser-level interaction, offline recovery and no-JavaScript behavior.
- Cross-browser and assistive-technology compatibility.
- Live deployment, response headers, social previews and Netlify form delivery.

The local Service Worker revision mismatch was a confirmed finding, not an untested limitation.

## Final assessment

**Historical readiness:** One release-integrity issue remained open.
**Senior rating:** 8/10.

The project showed strong source organization, deterministic build contracts, consistent document semantics and improved automated regression coverage.

All original P1 and P2 findings were resolved, and the three selected quality improvements were completed. However, P2-08 prevented an unconditional release-ready assessment.

The 8/10 rating reflects the verified repository state and incomplete production and browser-level evidence as of 2026-09-04.
