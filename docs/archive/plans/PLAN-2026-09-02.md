# Axiom — Development Plan

**Period:** 2026-08-30 to 2026-09-02
**Completed:** 2026-09-02
**Status:** COMPLETED — all six phases and two optional improvements implemented and verified.
**Scope:** Repository maintenance, production delivery, asset optimization, metadata, QA and documentation.

## Overview

The development plan addressed repository and deployment inconsistencies identified during the August 2026 technical audit.

Completed work established deterministic production assets, improved cache management, reduced unused files, consolidated source ownership and expanded automated verification.

All planned tasks were completed without introducing a frontend framework or runtime dependencies.

## Phase 1 — Delivery and repository contracts

- [x] **PH1-01 — Add ignore rules for dependency and build directories:** Added root `.gitignore` rules excluding dependency installations, generated production output and QA reports.
- [x] **PH1-02 — Align the cache policy with the built output paths:** Corrected caching rules for production bundles and unversioned resources; subsequent content hashing enabled immutable caching for fingerprinted bundles.
- [x] **PH1-03 — Give the root service worker a declared owner:** Established `sw.template.js` as the canonical source for generated local and production Service Workers.

## Phase 2 — Asset payload and reference integrity

- [x] **PH2-01 — Add an automated reference-integrity check:** Added `npm run qa:references` to validate local references and report unresolved assets and links.
- [x] **PH2-02 — Reduce the shipped image set to referenced files:** Reduced generated image variants and removed unused originals, retaining assets required by page references and responsive image declarations. Completed after PH2-01.

## Phase 3 — Public content and metadata

- [x] **PH3-01 — Correct the indexing policy on utility pages:** Applied `noindex, follow` to the offline and error pages through canonical page metadata.
- [x] **PH3-02 — Establish a single source for structured data:** Removed unused structured-data files and retained inline JSON-LD as the maintained source.
- [x] **PH3-03 — Align consent behavior with the cookie policy:** Corrected the Cookies Policy to describe the acceptance-only mechanism implemented at the time.

## Phase 4 — QA workflow and focused tests

- [x] **PH4-01 — Make the QA audits runnable without a manual server step:** Automated local server startup, readiness checks and cleanup for Lighthouse and pa11y runners.
- [x] **PH4-02 — Add focused tests for the contact form and the lightbox:** Introduced Vitest/jsdom coverage for form validation, message persistence, keyboard interactions and lightbox focus management.

## Phase 5 — Repository cleanup

- [x] **PH5-01 — Resolve inert configuration and dead code:** Removed unused redirect configuration, PostCSS configuration and the inactive FAQ module; aligned the production copy contract.

## Phase 6 — Documentation contract sync

- [x] **PH6-01 — Update documentation for the delivered changes:** Updated README and changelog content to reflect implemented build, asset, structured-data and Service Worker contracts. Completed after PH1-02, PH2-02 and PH3-02.

## Optional improvements

- [x] **O-01 — Content-hashed filenames for production bundles:** Introduced deterministic SHA-256-based CSS and JavaScript filenames, a shared build manifest, manifest-driven production references and immutable cache rules for fingerprinted assets. Extended reference validation to production output.
- [x] **O-02 — Record third-party font licensing in the repository:** Added upstream OFL license files and centralized third-party attribution, with corresponding references in the project documentation.
